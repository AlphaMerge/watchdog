**The split is the finding.** Both variants that pay 5,000 HTTP requests and
5,000 transactions got slower; the variant that pays one request for the same
5,000 objects got faster. So whatever is drifting is in the PER-REQUEST path,
not in the inserts -- which is consistent with `S-16`'s conclusion that the
remaining per-object write work is genuinely needed, and inconsistent with
blaming the writes.

Nothing committed since 2026-09-07 obviously explains it. `P-189` added a map
and a method to the probe endpoint, which no object create touches. `P-191`
removed one entry from `ALWAYS_PUBLIC`, which every request does consult --
but that shortens the list from four to three, which is the wrong direction.

suggestive, not conclusive, and two of the three have no recorded provenance.

That is `P-193`, and it is the next thing to do here -- not moving the budget,
and not hunting a regression blind.
