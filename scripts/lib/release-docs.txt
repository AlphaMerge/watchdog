# What a release ships of docs/, installed as /opt/ms/docs (`H-51`).
#
# `scripts/package.sh` stages the `ship` lines and nothing else, so the tarball, the .deb, the
# .rpm and the MSI all carry this set. It used to copy the whole directory, which installed the
# backlog, the roadmap, the scope contract, every design record and every measurement on every
# host. A `keep` line stays in the repository: it is written for whoever works on the code, or it
# records how a number was measured, and the shipped documents state what an operator needs of it.
#
# Every entry at the top of docs/ is on exactly one line, so a new document is decided here when
# it is added. `packages/core/test/release-docs.test.ts` holds that, holds every document a unit,
# an installed script or a string in the source names to a `ship` line, and fails on a link from
# a shipped document to one that is not shipped. `package-provenance.test.ts` holds what
# `package.sh` stages to this list.
#
# One entry a line, `ship` or `keep` and a path relative to docs/; a directory ends in `/` and can
# only be kept. The reason for a line is the comment above it.
